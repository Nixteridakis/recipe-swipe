# Recipe Book Importer – Chrome extension

Extracts JSON-LD `Recipe` data from the **current tab** and sends it to your Brasserie app. Because the recipe runs in the real browser session, you avoid server-side **403** blocks when importing.

The in-app **Import** page (`/import`) matches this flow: **extension first** (best), **paste URL** (quick), **paste HTML** (fallback when fetch is blocked).

## API URL (baked at zip time — no user setup in Chrome)

The extension reads **`chrome-extension/api-base.js`** (`RECIPE_BOOK_API_BASE`, no trailing slash). That file is generated by two flows:

| Command | Env variable | Default |
|--------|----------------|---------|
| **`pnpm run zip:extension`** (manual / local testing) | `NEXT_LOCAL_APP_URL` | `http://localhost:3000` |
| **`pnpm run build`** | `NEXT_PUBLIC_APP_URL` | warns + falls back to localhost if unset |

Both write **`chrome-extension/api-base.js`** and **`public/downloads/brasserie-recipe-importer.zip`**.

**Typical workflow:** use **`pnpm run zip:extension`** while developing (points at localhost unless you set `NEXT_LOCAL_APP_URL`). Run **`pnpm run build`** before deploy so the downloadable zip matches your public site (`NEXT_PUBLIC_APP_URL` in `.env.local` / CI).

**Note:** After a production build, `api-base.js` in the repo will contain the production URL. Run **`pnpm run zip:extension`** again when you want to go back to local Load unpacked testing.

## Get the extension

- **From the app:** On **`/import`**, use **Download extension (.zip)**, unzip anywhere, then load the unpacked folder in Chrome (the folder that contains `manifest.json`).
- **From the repo:** Use the `chrome-extension/` directory directly (same files as the zip).

## Load in Chrome

1. Open `chrome://extensions`
2. Turn on **Developer mode**
3. Click **Load unpacked**
4. Select the unzipped extension folder, or this repo folder: `chrome-extension/`

## Use

1. Open a recipe page in a tab (e.g. a site that publishes `Recipe` JSON-LD).
2. Click the extension icon.
3. Click **Import to Recipe Book** — extracts, normalizes via `/api/parse-recipe`, then saves via `/api/create-recipe`.
4. Optional: **Copy JSON** for debugging, or **Debug JSON-LD** if extraction fails.

## Compared to URL-only import

- **Extension**: uses the live DOM / JSON-LD from your session — no bot blocking.
- **Paste URL**: server fetches the URL; some sites return 403 or hide content.
- **Paste HTML** (Import page): paste **View source** HTML when fetch fails; optional URL field improves the stored `sourceUrl` in Sanity when provided.
